GeoPT 动态 CFD：从网络改造到当前阶段的完整工作报告

更新时间：2026-08-05  

研究对象：奔跑/行走机器人外流场的瞬态变边界 CFD 代理模型  

当前阶段：DynamicTransolver V0 已实现并完成真实 CFD 序列过拟合诊断；动态泛化与公开基准测试尚待开展

1. 工作概览

在完成 GeoPT 静态风场验证后，研究重点由“固定机器人几何、改变来流条件的稳态预测”转向：

给定当前流场、当前与下一时刻的机器人边界状态，预测下一时刻的三维流场。

围绕这一目标，目前已完成以下工作：

  1. 将静态 GeoPT/Transolver 改造成显式的单步动态状态转移模型 DynamicTransolver V0。

  2. 保留 GeoPT 预训练骨干及其 14 维静态输入接口，新增上一帧流场和移动边界特征编码器。

  3. 定义动态 CFD 数据契约、固定欧拉点集、掩码、归一化、checkpoint 迁移和 rollout 评估流程。

  4. 审计生成的 H1 动态 OpenFOAM 资产，确认其可用于方法诊断，但当前仍属于 legacy diagnostic 数据，而非最终高保真训练集。

  5. 完成单转移、200 帧序列、GeoPT 与随机初始化对比，以及 30,000 点、1,000 epochs 的强化过拟合实验。

  6. 定位并修复动态网格上 pv.sample() 插值产生异常值的问题，改为基于包含单元的 cell-centered 场读取。

  7. 系统调研长时滚动误差控制方法，并制定从单步监督到多步课程学习、TBPTT 和稳定性正则化的实验路线。

  8. 调研 EAGLE、RealPDEBench 等公开动态 CFD 基准，形成可与已有论文直接比较的 benchmark 策略。

当前最重要的结论是：GeoPT 预训练确实为动态任务提供了更好的初始化，能够同时改善单步拟合和长时 rollout；但单步过拟合继续提升并不能自动解决自回归误差累积，后续研究中心应转向多步训练、状态完备性和公开基准泛化。

3.5 token 设计的当前边界

V0 没有加入跨时间持久化的 summary token。Transolver 原有 slice/physics token 会在每层、每次 forward 中由当前点集重新构造，它们负责当前帧的空间信息聚合，但不保存上一帧记忆。

当前的时间信息通过 previous_state 和 boundary_feat 显式注入。后续可按证据逐步研究：

  • V1：关节/link motion tokens，用于更紧凑地表达机器人运动学；

  • V2：跨帧 persistent latent tokens，用于携带历史流场摘要；

  • 只有在多步基线证明单帧状态不足时，再引入更复杂的时序记忆结构。

6. 数据导出问题与修复

6.1 原问题

早期数据导出使用 PyVista 的 pv.sample() 将动态 OpenFOAM 网格上的场插值到固定查询点。动态边界附近存在：

  • 查询点跨越 fluid/solid 区域；

  • 每帧网格拓扑和单元分布变化；

  • cell field 被转换为 point field 后再插值；

  • 边界附近缺少稳定的有效邻域。

这些因素会产生非物理的大速度或压力值。最明显的异常出现在 570 -> 575 ms 转移，但这并不是原始 OpenFOAM 场损坏；异常主要由我们的重采样路径引入。

6.2 修复方法

修复后不再使用 pv.sample()：

  1. 对固定欧拉查询点定位其所在 OpenFOAM cell；

  2. 直接读取该 cell 的 cell-centered U 和 p；

  3. 对流体有效性、速度上界和有限值进行门控；

  4. 所有点数配置使用同一固定点库的嵌套子集。

修复后，8192 点、300 epochs 的同配置 GeoPT 结果变化为：

数据版本 单步相对 L2 rollout 均值 rollout 最终步
原 pv.sample() 导出 0.1869 0.5837 0.7421
cell-centered 修复后 0.0730 0.4837 0.6160
相对改善 60.9% 17.1% 17.0%

这说明数据提取质量会显著影响模型误差，尤其影响单步拟合；但修复采样后 rollout 仍明显高于单步误差，说明长时不稳定并不只是一个坏帧造成，误差累计显著。

10. 为什么单帧拟合较好，但 rollout 仍不稳定

单步 teacher forcing 训练时，模型每次看到的 Y_t 都是真值；rollout 推理时，从第二步开始输入包含模型自己的误差。这形成分布偏移：

当前误差来源至少包括：

  1. 暴露偏差：训练没有充分见过带预测误差的输入状态。

  2. 训练目标不匹配：单步 loss 不直接优化 50、100 或 199 步后的误差。

  3. 瞬态放大：单步映射的局部 Jacobian 可能在某些方向放大小扰动。

  4. 部分观测：当前 [U,p] 不包含 SST 的 k,omega，不同隐含湍流状态可能对应相近的可见状态。

  5. 变边界困难区域：新增 21,808 个点增加了近壁面、新暴露流体和尾流区域的比例。

点数增加本身不会必然导致不稳定。旧 30k 实验在共同的 8192 点子集上反而优于 8192 模型，说明更多点改善了已见区域；整体 rollout 恶化主要来自新增的高难度点及旧插值异常。修复数据并增加训练后，30k 模型的单步和 rollout 都得到提升。

11. 长时动态 PDE 方法调研

围绕上述问题，已完成长时 PDE surrogate 文献调研，形成三类方法路线。

11.1 输入扰动与恢复训练

  • Learning to Simulate Complex Physics with Graph Networks (GNS)：向训练状态加入噪声，使模型学习从偏离真值轨迹的状态恢复。

  • Message Passing Neural PDE Solvers (MP-PDE)：使用 temporal bundling 和 pushforward trick，让训练输入逐渐接近推理时的模型状态。

  • DCCL：在教师状态和模型预测状态之间连续插值，并随训练推进逐渐增加预测状态比例。

这类方法与现有 DynamicTransolver 最兼容，优先级最高。

11.2 多步展开与课程学习

  • 从单步 horizon 逐步增加为 1 -> 4 -> 8 -> 16；

  • 比较 NOG（不通过 rollout 反传）、WIG（完整展开梯度）和 TBPTT（截断时间反向传播）；

  • 使用多步加权 loss，使训练目标与最终 rollout 指标一致。

TBPTT 的含义是：模型连续展开多个时间步，但只在有限窗口内保留反向传播计算图。它比完整序列反传节省显存，同时仍能让梯度看到多步误差。

11.3 动力系统稳定性约束

“Controlling Transient Amplification”指出，即使特征值看起来稳定，非正规 Jacobian 仍可能短时放大扰动。后续可监测或约束：

  • 局部状态转移 Jacobian 的放大率；

  • latent dynamics 的 normality/commutativity；

  • 长时间段中的误差增长率。

该方向适合作为多步训练基线之后的增强项，不应先于基本 rollout curriculum。

11.4 推荐实验顺序

阶段 方法 目的
E0 干净 cell-centered 单步基线 建立可信下限
E1 状态噪声 学习局部误差恢复
E2 Pushforward / stop-gradient 缩小训练-推理输入差异
E3 DCCL 连续增加预测状态占比
E4 Horizon 1->4->8->16 直接优化长时误差
E5 NOG vs WIG vs TBPTT 比较精度、显存和训练时间
E6 加入 k,omega 检验状态完备性
E7 Jacobian 稳定性诊断/正则 控制瞬态放大

12.2 RealPDEBench：跨真实与数值 CFD

RealPDEBench 提供真实实验与数值 CFD 的配对任务，并包含 Transolver、DPOT 等公开基线：

  • Controlled Cylinder：强迫振动圆柱，96 条真实与 96 条数值轨迹；

  • FSI：流固耦合，51 条真实与 51 条数值轨迹；

  • 支持 numerical-only、real-only、numerical pretrain -> real finetune。

它适合回答“预训练是否改善真实动态 CFD 预测”和“DynamicTransolver 是否优于原 Transolver”等问题。但数据位于固定欧拉网格，未显式提供 SDF 和壁面速度，不能单独证明当前动态边界特征设计的优势。

13. 当前能够支持的结论

13.1 已有证据支持

  1. 原 GeoPT 静态骨干可以在不破坏 14 维预训练输入的前提下改造成动态单步状态转移器。

  2. GeoPT 初始化在同一 200 帧诊断数据上优于随机初始化，尤其显著降低 rollout 误差。

  3. 动态 CFD 数据的抽样方式会显著影响模型误差，移动边界附近必须避免不受控的 point interpolation。

  4. 30k 点、1000 epochs 能继续降低单步和 rollout 误差，且达到约 60 FPS 的模型推理速度。

  5. 仅增加点数和单步 epochs 不足以达到严格长时 rollout 门槛。

13.2 当前不能声称

  1. 不能声称已完成动态姿态泛化：目前训练和评估使用同一条 200 帧轨迹。

  2. 不能声称已达到高保真动态 CFD 精度：当前 legacy 标签为 diagnostic-only。

  3. 不能声称优于公开 SOTA：EAGLE/RealPDEBench 尚未实际训练和跑分。

  4. 不能把模型相对 OpenFOAM 的加速比作为正式结论：还需统一硬件、预处理和完整端到端计时。

  5. 不能仅凭单步误差说明长时预测稳定。

14. 下一阶段计划

14.1 近期：解决 rollout 稳定性

  1. 在 cell-centered 数据上固定 E0 基线。

  2. 依次加入状态噪声、pushforward 和 DCCL。

  3. 使用 1 -> 4 -> 8 -> 16 horizon curriculum。

  4. 在同一显存预算下比较 NOG、WIG 和 TBPTT。

  5. 同时报告 +1、+10、+25、+50、+100、最终步误差与误差增长曲线。

14.2 中期：提高数据与状态质量

  1. 获取多条动作、cadence scale（步频缩放）和 amplitude scale（动作幅度缩放）轨迹。

  2. 使用 strict-V2 动态 CFD，保证拓扑、守恒量、力和力矩连续性。

  3. 将 k,omega 纳入状态，验证当前系统是否受部分观测限制。

  4. 按完整轨迹划分 train/validation/test，禁止相邻帧泄漏。

14.3 公开比较

  1. 先复现 EAGLE 官方基线和指标脚本。

  2. 在同一划分、同一 rollout horizon 下运行 DynamicTransolver。

  3. 在 RealPDEBench 上比较 Transolver、GeoPT 初始化和 DynamicTransolver。

  4. 最终回到 H1/G1，报告三维多关节场景中的精度、稳定性、显存和端到端速度。

16. 组会汇报

本阶段可凝练为四项贡献：

  1. 架构贡献：完成从静态 GeoPT 到显式变边界动态状态转移器的最小兼容改造，并成功迁移 165/169 个预训练张量。

  2. 实验贡献：在真实 H1 连续 CFD 上完成单转移和 200 帧过拟合诊断；GeoPT 相比随机初始化将初始 8192 点 rollout 均值误差降低约 53.3%。

  3. 工程贡献：定位动态网格插值异常并改为 cell-centered 读取；修复后单步误差降低约 60.9%。

  4. 研究推进：30k/1000 epochs 将单步均值降至 0.0426、199 步 rollout 均值降至 0.3672，同时明确下一瓶颈是多步稳定性而非继续堆叠单步 epochs；已建立 EAGLE、RealPDEBench、自有 H1/G1 的三级评价路线。

最审慎且有信息量的阶段性表述是：

我们已经证明 GeoPT 的空间预训练表征可以迁移到真实变边界瞬态 CFD，并明显优于随机初始化；同时，实验揭示了动态网格数据提取和长时误差累积是两个独立问题。下一阶段将以多步课程学习和公开 benchmark 为中心，验证该优势能否从轨迹内过拟合扩展到跨轨迹、跨动作和公开数据集泛化。
