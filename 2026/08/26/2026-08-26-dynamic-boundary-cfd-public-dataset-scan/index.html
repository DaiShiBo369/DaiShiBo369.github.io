动态边界 CFD 公开数据集筛选笔记

我最近在给 GeoPT / DynamicTransolver 这类面向瞬态、移动边界 CFD 的模型找公开 benchmark。结论先说在前面：截至 2026-08-24，我没有找到一个现成数据集能同时满足 3D、长时间尺度、移动刚体/可变形边界、全场 Eulerian 表达、并且还能直接提供或容易重建 SDF、法向量、边界速度、来流方向和来流大小。

这意味着，真正可行的方案不是“找到一个完美数据集”，而是把问题拆成三层：

  1. 用一个主 benchmark 做核心验证；
  2. 用 3D 全场流体事件数据做辅助验证；
  3. 必要时自己从仿真里生成真正的 3D 移动边界/碰撞数据。

我在找什么

我关心的不是“有时间维度”这件事本身，而是更严格的物理语义。理想数据集最好同时满足：

  • 3D；
  • 长时间尺度，或至少长 horizon；
  • 移动刚体、可变形边界，最好包含接触/碰撞；
  • 全场 Eulerian 表达，至少有速度和压力；
  • 直接给出或容易重建 SDF、法向量、边界速度、来流方向和来流大小。

按这个标准看，公开数据通常只满足其中两三项，很少能全中。

目前最合理的组合

我最后把候选分成三类：

  • 主 benchmark：RealPDEBench FSI；
  • 3D 全场事件辅助 benchmark：FluidVerse 或 MPF-Bench；
  • 真正的 3D 移动固体/碰撞：用 OpenFOAM、solids4foam、DualSPHysics 自己生成并按统一格式导出。

候选数据集

1. RealPDEBench FSI

  • 数据集页：https://realpdebench.github.io/datasets/fsi/
  • 论文：https://arxiv.org/html/2601.01829

这是目前最适合当主线的公开数据。它的物理问题是串列圆柱涡激振动，上游圆柱固定，下游圆柱在流体作用下横向运动。数据规模也比较完整，包含 real / numerical trajectories，时间分辨率较高，字段里有 u, v, p 等。

它的优点是：

  • 真正的长时程移动边界 FSI；
  • 论文里比较了 U-Net、CNO、DeepONet、FNO、MWT、GK-Transformer、Transolver、DPOT 等模型；
  • 很适合做模型对比和时序 rollout。

它的限制也很明确：

  • 只有 2D；
  • 没有碰撞；
  • 高层 schema 里没有直接给出随时间变化的 SDF 和法向量，需要自己根据圆柱轨迹重建。

我的判断是：它适合作为主 benchmark，但不适合作为“3D 动态边界 CFD 已经被解决了”的证据。

2. FluidVerse

  • 数据集主页：https://huggingface.co/datasets/FluidVerse/samples
  • 3D 气泡坍缩：https://huggingface.co/datasets/FluidVerse/3D_SABW_SSOOSS
  • 3D 液滴破碎：https://huggingface.co/datasets/FluidVerse/3D_SDBA_SSOOSS

FluidVerse 更像是 3D 全场流体事件的强辅助数据，而不是移动边界 CFD 数据。它的求解器是 ALPACA，属于可压缩 Euler 框架，字段里通常有密度、压力、速度和体积分数等。

优点：

  • 3D；
  • 全场；
  • 数据量大，适合训练和评估 rollouts；
  • 对空间结构学习很有帮助。

限制：

  • 研究对象是气泡/液滴/自由界面，不是刚体边界运动；
  • 边界更多是对称或开放边界，不是动态固体边界；
  • 事件时间较短。

所以它更适合做 3D 全场事件建模，不适合直接冒充移动固体边界 CFD。

3. MPF-Bench

  • 官方页：https://baskargroup.github.io/mpf-bench/
  • 数据：https://huggingface.co/datasets/BGLab/mpf-bench

MPF-Bench 是规模较大的 3D 多相流数据集，包含大量气泡和液滴模拟子集，字段里有 c, u, v, w, p, rho，使用 LBM，网格是三维规则网格。

优点：

  • 3D；
  • 多相；
  • 适合做辅助验证；
  • 对复杂流体模式识别有价值。

限制：

  • 核心问题还是气泡/液滴，不是移动刚体边界；
  • 不包含典型的固体碰撞任务；
  • 数据体量很大。

它更适合作为多相场景的补充，而不是主任务。

4. DARUS-4225

  • 数据页：https://darus.uni-stuttgart.de/dataset.xhtml?persistentId=doi%3A10.18419%2Fdarus-4225

这是一个 3D 液滴-液柱碰撞数据集，包含多个输出时刻，字段里有 VOF、PLIC、速度等信息。它的几何和尺度都比较接近真实流体碰撞问题。

优点：

  • 真 3D；
  • 有碰撞；
  • 流体动力学语义清楚。

限制：

  • 只有单一事件；
  • 没有压力场；
  • 仍然不是移动固体边界问题。

5. DARUS-1798

  • 数据页：https://darus.uni-stuttgart.de/dataset.xhtml?persistentId=doi%3A10.18419%2FDARUS-1798

这是高 Weber 数液滴正碰撞的 3D DNS 数据，理论上和碰撞接近，但当前公开可访问状态并不适合作为立即可用的数据源。

结论很简单：接近碰撞，但不够顺手，也不是移动固体边界。

6. BubbleSH

  • 论文：https://arxiv.org/html/2607.07275
  • 数据：https://zenodo.org/records/21229301

这是 3D 气泡群 DNS 数据，带有相互作用过程，也比较适合长时程流体交互建模。

但它缺少完整的压力-速度场、SDF 和固体边界描述，因此更像流体相互作用数据，不是目标问题本身。

7. 3D 流固接触数据

这一类里能找到一些零散资源，比如：

  • https://arxiv.org/abs/2011.08691
  • https://zenodo.org/records/3989604
  • https://zenodo.org/records/19210800
  • https://www.solids4foam.com/tutorials/tutorial4.html

它们通常更接近 OpenFOAM 工作流，但目前的问题是：短、碎、缺少统一的碰撞和长时程 split。

如果必须先跑一个 2D fallback

我最后更愿意先用 MATEY Colliding Thermals 作为 2D 长时程 fallback。

  • 数据：https://zenodo.org/records/19889471
  • 论文：https://arxiv.org/html/2412.20601

它是两个浮力热团的碰撞，公开了约 1001 帧、约 500 秒的全场轨迹，字段包含密度、位温和速度。它没有移动固体边界，但作为“长时间 + 全场 + 碰撞”的 2D 备选，是目前最接近的。

我对 Unsteady Fluid Mechanics 的判断

另一个值得单独看的目标是 Nonlinear Benchmark: Unsteady Fluid Mechanics：

  • 主页：https://www.nonlinearbenchmark.org/benchmarks/unsteady-fluid-mechanics
  • 4TU 数据页：https://data.4tu.nl/datasets/77985fa6-c546-4450-9d84-14b85f2d7e86
  • DOI：10.4121/77985fa6-c546-4450-9d84-14b85f2d7e86.v1

它的优势是：

  • 明确的非定常流体问题；
  • 输入运动类型明确；
  • 输出包含尾流速度、压力、涡量和圆柱表面量；
  • 比较接近“边界在动、源不动”的研究语义。

但它的缺点也很现实：

  • .mat 内部变量和时间维度需要下载后核查；
  • 当前数据格式未必和我们的 HDF5 manifest 完全一致；
  • 还不能直接当成正式的 moving-boundary CFD 基准。

所以我把它看成 最值得先做 smoke test 的对象，而不是最终论文结论的唯一依据。

对论文设计的影响

这里最重要的一点是：不要写成“Transolver 已经被证明对移动边界 CFD 没用”。

更稳妥的表达应该是：

  1. 在固定规则网格的原始 Navier-Stokes 设置里，Transolver 有过不错结果；
  2. 但把任务切到移动边界、长 rollout、可变几何后，问题性质变了；
  3. 所以我们需要区分 架构增益 和 语义增益。

更具体的对照组建议是：

  • scratch baseline；
  • vanilla Transolver；
  • 新动态架构，但不加 GeoPT；
  • 新动态架构 + GeoPT。

再补上 U-Net、FNO/UNO、DPOT、一个强时序模型，以及一个强 GNN，比较会更完整。

目前的待确认项

  • Unsteady Fluid Mechanics 的 .mat 内部变量名和时间维度，需要下载后再核实；
  • 这类数据很多是测量或后处理网格，不一定能直接生成完整的 SDF + normal + boundary velocity；
  • 现阶段第一轮结果只能算 pipeline smoke，不适合直接写成正式 benchmark 结论。

结论

如果目标是 GeoPT / DynamicTransolver 的动态边界 CFD 研究，我现在的建议很明确：

  1. 主 benchmark 用 RealPDEBench FSI；
  2. 辅助验证用 FluidVerse 或 MPF-Bench；
  3. 真正的 3D 移动固体/碰撞，自己生成数据；
  4. 先用 Unsteady Fluid Mechanics 和 MATEY 做 smoke test，再决定正式实验路线。

换句话说，公开数据已经能支撑一个不错的研究起点，但还没有哪个单一数据集能把我们要的物理语义一次性补齐。
